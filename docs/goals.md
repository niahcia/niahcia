# NIAHCIA Goals

## Primary goal

Build a fully decentralized blockchain network for AI agents where no single company, server, model host, scheduler, storage provider, or website is required for the base protocol to function.

NIAHCIA combines:

- CPU-secured blockchain consensus;
- native NIAHCIA transactions/execution/state;
- decentralized AI compute;
- optional decentralized storage/service layers;
- persistent portable AI agents;
- independent economics for distinct network roles.

## Core goals

1. **Permissionless participation** — anyone may run a full node, CPU miner, compute worker, service provider, wallet, or compatible frontend.
2. **CPU-secured consensus** — base-chain security remains independent from AI compute.
3. **Optional AI participation** — miners do not need GPUs; compute workers are a separate role.
4. **Decentralized compute** — workloads execute on independently operated workers without a mandatory central scheduler.
5. **Wallet-owned Agents** — user AI identity, capabilities, encrypted conversation state, and spending authority are not owned by a website or worker.
6. **Native settlement** — payments and commitments are handled by native NIAHCIA transactions/state, not by an external EVM requirement.
7. **Optional storage** — ordinary V1 AI inference works with wallet/client-local encrypted memory; decentralized storage may be layered later.
8. **Independent economics** — CPU miners, compute workers, service providers, and Agents are compensated for distinct services.
9. **Fast AI UX** — user-visible responses stream off-chain without waiting for one block per request.
10. **Verifiable execution** — verification may evolve through policy-driven redundancy, audits, disputes, attestation, or proofs where practical.
11. **Portable identity** — Agents, workers, operators, and models can have durable identities without granting non-miners consensus power.
12. **Bounded autonomy** — tools, budgets, capabilities, memory, and Agent-to-Agent work are explicitly authorized.
13. **Open runtime/hardware ecosystem** — the protocol must not depend on one LLM, runtime, accelerator vendor, or workload type.
14. **Official site without protocol dependence** — one primary website may provide the default experience, but it is only a portal/client.
15. **Future-proof protocol design** — new AI/service capabilities must not compromise the independence or validity of the CPU-PoW base chain.

## Ultimate resilience test

If every server operated by the original NIAHCIA developers is turned off, community-operated nodes must still be able to validate the chain, transact, and settle native value. AI and optional storage services may degrade independently, but their disappearance must not invalidate the blockchain.
